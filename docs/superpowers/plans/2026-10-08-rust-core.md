# CV Decisions — Rust Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Rust backend: the SQLite store, model downloads, the llama.cpp decision sidecar, the matcher, the Typst page-fit renderer, and the Tauri commands. The UI plan (Plan 2) builds on this one.

**Architecture:** Five modules under `src-tauri/src/` (`store`, `models`, `engine`, `matcher`, `render`), plus `commands.rs` exposing them to the webview. Inference goes through a `DecisionEngine` trait. `LlamaSidecar` is the production implementation; `FakeDecisionEngine` is used in tests.

**Tech Stack:** Rust 2021, Tauri 2, `sqlx` (sqlite, runtime-tokio, migrate), `tokio`, `reqwest` (json), `hf-hub` (tokio), `sha2`, `typst-as-lib` + `typst-pdf`, `tauri-plugin-shell`, `serde`, `thiserror`. Dev-only: `pdf-extract`, `tempfile`.

**Spec:** `docs/superpowers/specs/2026-10-08-cv-decisions-design.md`

## Global Constraints

- Offline after the model download; the only network use is the `hf-hub` download.
- The MVP never generates or rewrites text. The PDF contains only the user's stored text.
- The sidecar binds to `127.0.0.1` on a random free port, starts lazily, and is killed on app exit.
- Default model: Clef-flash. Optional: Clef 27B. Fallback: Kev-4B (subject to the outcome of Task 1).
- Relevance rubric: `score` on a 0–4 scale. Question batches are capped at 128.
- Page budget: 1 (default) or 2. Every included entry keeps at least 1 bullet. Bullets are dropped before whole entries.
- Template: "Classic ATS". Single column. Headings exactly: `Experience`, `Projects`, `Education`, `Skills`.
- All `cargo` commands run from `src-tauri/`.

## Review Focus

1. **A JD longer than the model's context window.** Expect a clear `EngineError::ContextOverflow`, not a crash or a silently truncated score → test in Task 4.
2. **Special characters in user text** (`#`, `$`, `*`, `_`, `@`, `<`), which are markup in Typst. Expect them to render literally → test in Task 7.
3. **An entry with zero bullets, or a library with no skills.** Expect the matcher to skip the bullet/skill calls and still produce a selection → test in Task 6.
4. **An item that can never fit, e.g. one huge entry on a 1-page budget.** Expect the fit loop to stop, never loop forever, and report an overflow → test in Task 8.
5. **A sidecar that dies mid-run.** Expect one automatic restart, then `EngineError::Unavailable`, with the partial scores persisted → test in Task 5 (restart) and Task 6 (partial scores).

### Task 8: Page-budget fit

**Files:**
- Create: `src-tauri/src/render/fit.rs`
- Test: `src-tauri/src/render/fit_tests.rs`

**Interfaces:**
- Consumes: `Ranked` (Task 6), `compile` / `CvDoc` (Task 7)
- Produces:
  - `struct Selection { entries: Vec<SelectedEntry>, skills: Vec<String> }`, `SelectedEntry { entry_id, bullet_ids: Vec<i64>, pinned: bool }` (serialized as `cv.selection_json`)
  - `enum Override { Include(Target), Exclude(Target), Order(Vec<i64>) }`, `Target { Entry(i64), Bullet(i64) }`
  - `fn fit(ranked: &Ranked, profile: &Profile, budget: u8, floor: f64, overrides: &[Override]) -> Result<FitResult, RenderError>`, `FitResult { selection, style: StyleStep, compiled: Compiled, overflow: bool }`

- [ ] **Step 1: Write the failing tests** (using real `compile`)
  - `never_exceeds_budget`: with 25 entries × 5 bullets and budget 1, `compiled.pages == 1`.
  - `drops_bullets_before_entries`: in a case that slightly overflows, the dropped item is the lowest-scoring bullet, and the entry count is unchanged.
  - `min_one_bullet`: every selected entry has `bullet_ids.len() >= 1`.
  - `floor_respected`: an entry scored below `floor` is never auto-selected, even when there's room.
  - `date_order_within_section`: selected experiences are in descending `start_date` order, regardless of score.
  - `tighten_before_drop`: when a candidate fits only at StyleStep(1), the result keeps the candidate and has `style == 1`.
  - `oversized_terminates` (Review Focus 4): a single entry whose 1 bullet is 4000 characters returns `Ok` with `overflow == true`, after at most `candidates × 3` compiles.
  - `override_exclude_wins`: excluding the top entry removes it, and the next candidate fills the space.
- [ ] **Step 2:** Run `cargo test render::fit` and check it fails.
- [ ] **Step 3:** Implement the fit as spec §5 describes. The base is the header, the top entry with its top bullet, and the skills. The candidate queue is: each entry with its top 2 bullets, then single bullets, all sorted by score. Apply the overrides first; included items count as pinned. For each candidate, try StyleStep 0, 1 and 2 before rejecting it.
- [ ] **Step 4:** Run `cargo test render::fit` and check that the tests pass.
- [ ] **Step 5:** Commit with the message `feat(render): greedy page-budget fit with tightening`.
