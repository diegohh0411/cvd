# CV Decisions — Frontend Implementation Plan (Plan 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Angular 22 + ZardUI presentation layer from spec §7: the `sidebar-07` shell, the Library, the Job workspace (New → Matching → Review → Export), Models, Settings and the first-run dialog. All logic stays in Rust; the webview only calls the commands from Plan 1 Task 9.

**Architecture:** Standalone components, signals everywhere, zoneless change detection. One typed IPC layer (`src/app/core/ipc/`) wraps every `invoke()` and `listen()`; feature stores (signal-based services) sit on top of it; components only read store signals and call store methods. Nothing outside `core/ipc` imports `@tauri-apps/api`.

**Tech Stack:** Angular 22 (standalone, signals, new control flow, `@angular/build`), ZardUI (shadcn-style, copied into `src/app/shared/components/` via its CLI), Tailwind CSS v4, `@angular/cdk/drag-drop`, `@tauri-apps/api` v2, `@tauri-apps/plugin-dialog` (save dialog), pdf.js (`pdfjs-dist`) for the live preview, Vitest via `@angular/build:unit-test` for component tests. Package manager: bun.

**Spec:** `docs/superpowers/specs/2026-10-08-cv-decisions-design.md` (§7 UI/UX, §8 errors, §9 Angular tests)
**Depends on:** `docs/superpowers/plans/2026-10-08-rust-core.md` (landed: `src-tauri/src/commands.rs`, `src-tauri/src/lib.rs`)

## Global Constraints

- The webview never touches SQLite, the model or the filesystem directly. The one exception is the save-path dialog, which only returns a path that is passed to `export_cv`.
- Never render or send generated text. The UI displays and reorders the user's own content only.
- Tauri command **argument names are camelCase** on the JS side (`runId`, `jdId`, `includeArchived`, `rawText`); payload **struct fields stay snake_case** (`start_date`, `bullet_ids`). Mirror the Rust types exactly; do not "fix" casing.
- Errors arrive as `{ kind: 'NotFound' | 'ModelMissing' | 'EngineUnavailable' | 'ContextOverflow' | 'Render' | 'Io', message: string }`. Every caller handles them through one `AppError` type.
- Events: `match://progress` → `{ run_id, event }` where `event.stage ∈ reading_jd | scoring_entries{done,total} | picking_bullets{done,total} | done | cancelled | failed{error}`; `model://download` → `{ id, done, total }`.
- Every route works with the sidebar collapsed to the icon rail and at a 900px-wide window.
- Keyboard: every action reachable without a mouse; drag-reorder also has Alt+↑/↓.
- All commands run from the repo root: `bun run …`.

## Backend gaps this plan closes (small, in Task 1)

The landed command list is missing a few reads the UI needs. Each is a thin wrapper over an existing `Store` method or state, with a test in `commands_tests.rs`:

| New command | Why | Backed by |
|---|---|---|
| `list_runs(jd_id)` / `latest_run(jd_id)` | Reopen a job in Review; Resume a cancelled run | new `Store::list_runs` (one `SELECT`) |
| `list_cvs(jd_id)` | Exports tab, Jobs › Exports | `Store::list_cvs` (exists) |
| `get_scores(run_id, target_type, target_id)` | Hover rubric breakdown (§7); `Ranked` has only the scalar score | `Store::scores_for_run` filtered |
| `get_role_signals(run_id)` | Role signals card: seniority + role family + skill probabilities | `scores_for_run`, `TargetType::Meta`/`Skill` |
| `engine_status()` | Sidebar footer `● Clef-flash · ready` | `AppState::active_model` + engine handle state (`idle | starting | ready | error{log_excerpt}`) |
| `cancel_download(id)` | Pause (spec §7 first run); resume = call `download_model` again, hf-hub resumes partial files | cancellation token like `cancel_run` |

Also: add `tauri-plugin-dialog` (Rust + `dialog:allow-save` in `capabilities/default.json`) and an `engine://status` event emitted on engine state changes.

> If any gap is contested in review, the UI fallback is noted in the task that uses it.

## Review Focus

1. **Out-of-order fit responses.** Rapid checkbox clicks fire several `fit_cv` calls; a slow older response must never overwrite a newer one → request sequence number, test in Task 9.
2. **Event before listener.** `start_match` returns a run id while the run already streams; progress emitted before `listen()` resolves would be lost → subscribe first, filter by `run_id`, and reconcile with `latest_run` on mount → test in Task 8.
3. **Large base64 PDFs** on every edit. Decode once into a `Uint8Array`, keep only the last good document, and never put the base64 string into a signal that templates read → Task 10.
4. **Typst compile error** mid-review: keep the last good preview and show the error (§8) → test in Task 10.
5. **Empty library**: Match disabled with a link to Library (§8); `start_match` returns `NotFound(EMPTY_LIBRARY)` as a backstop → test in Task 7.
6. **Overrides semantics.** `Override` serializes externally tagged: `{"Include":{"Entry":5}}`, `{"Exclude":{"Bullet":9}}`, `{"Order":[3,1,2]}`. A TS type that drifts from this is silent breakage → contract test in Task 2.
